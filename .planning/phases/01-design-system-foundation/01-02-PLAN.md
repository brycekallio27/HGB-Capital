Replace this block with the following:

```python
# --- 2. SIDEBAR ---

def _toggle_theme() -> None:
    """Callback: flip dark_mode in session_state before rerun."""
    st.session_state.dark_mode = not st.session_state.dark_mode

_theme_icon = "🌙" if st.session_state.dark_mode else "☀️"
st.sidebar.button(
    _theme_icon,
    on_click=_toggle_theme,
    help="Toggle dark/light mode",
    key="theme_toggle",
)

st.sidebar.header("Operations")
user = st.sidebar.selectbox("Partner Login", ["Partner A", "Partner B", "Partner C"])
st.sidebar.success(f"Active Session: {user}")
```

Implementation details:
- `_toggle_theme` is defined as a module-level function (not a lambda) to be referenceable by `on_click`. The leading underscore signals it is an internal helper.
- `on_click=_toggle_theme` uses the Streamlit callback pattern: Streamlit executes the callback BEFORE re-running the script, so `session_state.dark_mode` is already updated when the top-of-script `inject_css(st.session_state.dark_mode)` call fires. This eliminates the double-rerun flicker seen in the naive `if st.button(): st.session_state.x = ...; st.rerun()` pattern.
- `_theme_icon` reads the CURRENT `st.session_state.dark_mode` to show the icon representing the ACTIVE mode: 🌙 when in dark mode (click to stay/indicate dark), ☀️ when in light mode (click to switch to dark). Convention: show the current state icon (not the next state), consistent with how most toggle buttons work.
- `key="theme_toggle"` prevents key conflicts if Streamlit ever sees duplicate button labels.
- The button has zero label text — icon only, minimal sidebar footprint as specified in CONTEXT.md.
- The `st.sidebar.header("Operations")` line and everything below it is PRESERVED unchanged. The toggle is inserted ABOVE it.

Do NOT use `if st.sidebar.button(...): st.session_state.dark_mode = ...; st.rerun()` — this is the double-rerun anti-pattern documented in RESEARCH.md Pitfall 2.
Do NOT use `st._config.set_option()` — this affects all concurrent sessions globally (RESEARCH.md anti-patterns).
